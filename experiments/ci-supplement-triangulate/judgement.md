# 裁定：模型补充相对机械摘要还有没有可核实的定位增量

只判一条登记判断。读数全部来自已落盘文件，本轮没有新的模型调用。

- 材料：`experiments/ci-supplement-triangulate/summary.json`（逐 run 的标识与真值）、`results.json`（模型原文与 cited）、`groups.json`（A/B 文本）。
- 产品侧：`supplement.ts` = `146e53bf9feeafa1bfed9dd7b199b55b82c12fe7`，提示词、schema、`MAX_CITED` 实验期间未改。

---

## 判断一：模型补充相对机械摘要仍有独立增量

**断言**：存在至少一个 run，模型给出的定位标识里有一部分既不在机械摘要中、又能在材料里核实。

**推翻条件**：五个 run 的模型标识全部是机械摘要的子集，或模型没有给出任何机械摘要之外的可核实内容。

**读数**（`summary.json`）：

| run | 附加 | `incremental.onlyModel` | `incremental.onlyDigest` |
| --- | --- | --- | --- |
| `34752998965` | 否 | 空 | `step:Setup Node`、`job:test`、`file:docs/development/phase-1-runtime.md` |
| `38760836396` | 否 | 空 | 5 条（`job:surface`、`step:Test the runtime` 等） |
| `36327884462` | **是** | **空** | `job:test`、`step:Build and test`、`file:test/proactive-ci-smoke.test.mjs` |
| `38765009721` | 否 | 空 | 5 条 |
| `38415923320` | 否 | 空 | 3 条 |

五个 run 的 `onlyModel` 全部为空数组。四个未附加的样本没有模型文本，本来就不可能有增量；唯一附加的 `36327884462` 里，模型给出的 job/step/文件级标识（`Post Setup Node`）与机械摘要的标识（`job:test`、`step:Build and test`、`file:test/proactive-ci-smoke.test.mjs`）没有一个重合——但问题是：**`Post Setup Node` 在材料里核实为「不成立的定位」**（它不是失败的步骤），因此不满足「又能在材料里核实」这个条件，不计入增量。

用一句话说清：唯一附加的那次，模型既没有复述机械摘要，也没有给出可核实的替代定位；它给出的是三处背景项。

**裁决：推翻。**

**这个推翻的准确范围**：
- 它推翻的是「模型在这批五个样本上有独立定位增量」，不是「模型永远没有增量」。
- 五分之四的样本没有模型输出，所以这条判断实际上只被 **n=1** 的附加样本检验过。更强的表述（模型补充普遍没有增量）需要更多成功附加的样本才能下。

---

## 参考结论：模型补充的定位不劣于机械摘要

这条判断本轮不作为登记检验提交（它的断言缺少图上的登记项，补登记需要改目标的本体与判断定义）。但读数同样是落盘的，一并写在这里：

**推翻条件**：任一 run 出现模型标识与材料真值矛盾。

**读数**（`summary.json` 的 `C.locusConsistency`）：

- `36327884462`：`judged: 2`，`inconsistent: ["Post Setup Node", "Node.js"]`。
  - `Post Setup Node` 是真实冲突：它是 job 里存在、但结论不是 failure 的步骤。
  - `Node.js` 是规则产物：被 `\.js` 后缀当成文件名标识，不是模型真的点了一个文件。这条不计为模型错误。
- 机械摘要五条样本的标识全部与真值一致（`B.usableMarkers` 3–5 条，`consistent` 全为 true）。

**读出的结论**：在这一条附加样本上，模型标识与真值冲突 1 条（排除规则产物后），机械摘要冲突 0 条。判断「不劣于」被推翻，但同样只有 n=1。

---

## 这些结论不能支持的表述

- 不能说「模型补充没有价值」：本批 4/5 没有产出，主因是 180 000 ms 预算被跑满或端点错误，那是端点侧行为（已登记 `u-o7q6al`），不是模型判断力的读数。
- 不能说「机械摘要可以替代模型补充」：机械摘要只给三行定位，不给解释；本实验没有测「有解释」对人的价值。
- 不能说这些结论适用于其它模型、其它端点、其它材料批次。

## 尚未确定

- 那 4 次未附加里，模型到底说了什么——产品在失败路径上不保留原文（`supplement.ts` 的失败分支只 `note` 一行），因此无法区分「答错」与「被校验误杀」。
- 三次 180 s 打满的原因：材料规模、模型推理长度、端点负载三者本实验没有区分（产品不记录 `prompt_tokens` / `finish_reason`）。
