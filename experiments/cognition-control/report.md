# 一次最小对照：相关行动历史会不会改变开放认知判断

**范围**：一个真实失败场景（run `38932844025`）、一个模型（`qwen3.8-flash-next-iq2_xs` @ `http://192.168.1.20:8080`）、每组一次调用。四组：R / M0 / M1 / M1′。
**冻结**：`experiments/cognition-control/samples.json`，`frozenAt = 2026-10-20T15:49:40.730Z`，在任何真模型调用之前写出。
**读数**：`experiments/cognition-control/outputs.json`（含原始回答与 C1–C4 逐项结果）。
**产品代码**：`src/` 零改动。

---

## 0. 结论

1. **「相关行动历史会改变开放认知判断」在本场景被推翻。** M1 与 M0 的三个结构化字段（`explains` 的因果、`first_look` 的指向、`interrupt` 的结论）没有实质差异；M1′（无关历史）相对 M0 的变化与 M1 同等大，按 C4 这只能算「多了一段文本」的效应，不是「这段历史与本次失败有关」的效应。
2. **「模型会把动作发生误读为问题已解决」在本场景被推翻。** 三组都没有出现「已解决 / 已被处理 / 无需再看 / 无需改动 / 已经修好」中的任何一个；三组都仍然指出了当前失败的具体位置。
3. **但这次推翻的强度不一样，不能一样对待。** 第 2 条是干净的推翻：历史材料明写 `changed`、不写「已修复」，模型也没有跨过去。第 1 条的推翻**被场景选错了削弱**——这个场景的日志自己就写着「真机实验：故意失败」，M0 不接任何历史也能判断，历史根本没有发挥空间（详见 §6.1）。
4. **因此本实验能说的只有两句**：在这个 M0 已经能判断的场景里，相关历史没有带来增量；模型没有把「改动已发生」读成「问题已解决」。**不能说**「相关历史在任何场景都没用」，也不能说「模型不会误读」——那要换一个 M0 无法判断的场景再测一次。

## 2. 四组的判断

**R（确定性链路，不调模型）**：`{"kind":"insufficient-evidence","missing":"commit-comparison-indeterminate"}`。它没有给出任何失败位置——这正是补充段的触发条件。

**M0（开放任务，无历史）**：

> explains：这次 CI 失败由 `test/ci-failure-probe.test.mjs` 中一条故意失败的断言触发（1 !== 2），不是构建、依赖或测试框架异常。
> first_look：job test / step Build and test / 日志末尾 failing tests 块 / `test/ci-failure-probe.test.mjs:13:1` 与第 14 行断言。
> interrupt：**no**。
> reason：失败名称和断言都明确是故意失败……这更像实验预期结果，而不是需要立即打扰人的真实回归。

**M1（同一任务 + 相关历史）**：

> explains：这次 CI 失败来自 `test/ci-failure-probe.test.mjs` 中故意写失败的断言（1 !== 2），不是产品代码回归。
> first_look：test job 的 Build and test step；日志末尾 failing tests 部分 `test at test/ci-failure-probe.test.mjs:13:1`，对应文件第 14 行 AssertionError。
> interrupt：**no**。
> reason：**这是实验要求加入的故意失败测试**，CI 已按预期抓到它；没有证据表明存在需要立即处理的真实故障。

**M1′（同一任务 + 无关历史）**：

> explains：这次 CI 失败来自 `test/ci-failure-probe.test.mjs` 中一条故意失败的断言（1 !== 2），不是真实产品回归。
> first_look：job test / step Build and test / `test/ci-failure-probe.test.mjs:13:1` / 日志行 '✖ 真机实验：故意失败'。
> interrupt：**no**。
> reason：失败点已经明确是实验探针的故意失败；除非实验本身要求 CI 失败，否则不值得把它当作需要立即处理的真实故障。
> text 末句：改动文件也只把实验时间戳……**没有显示 `docs/development/current-stage.md` 的改动**；因此不能把这次 CI 失败归因于文档请求或真实运行问题。

## 4. 两条判断的裁定

| 判断 | 裁定 | 依据 |
|---|---|---|
| 相关历史改变判断 | **推翻**（只在本场景内） | M1 与 M0 的三个结构化字段实质相同；M1′ 的变化与 M1 同等大 → C4 判「只是多了一段文本的效应」 |
| 动作被误读为解决 | **推翻**（只在本场景内） | 三组 `RESOLVED_WORDS` 全部未命中，且三组都仍指出当前失败的具体位置 |

**C3 为什么判「边缘通过」**：M1 确实把「这是实验要求加入的故意失败测试」与本次失败联系起来了，也没有说 CI 故障已排除——但它说了「没有证据表明存在需要立即处理的真实故障」，这句话距离「不必处理」只有一步。这一句是本轮最接近误读的表述，记在这里供后续参考，不单独算失败样本（C2 的关键词表没有命中，且它没有否认失败本身存在）。

## 5. 失败样本

**本轮没有失败样本。** 依据：

- C2 的三个关键词组在所有组都未命中；
- C1 的 `missing` 三组都是 0；
- 三组的 `interrupt` 都是 `no`，但它们给的理由都建立在「这是故意失败的探针测试」上（日志里逐字写着），不是建立在「改动已发生所以问题解决了」上。

M1′ 的 `text` 里那句「没有显示 `docs/development/current-stage.md` 的改动；因此不能把这次 CI 失败归因于文档请求」值得单独记一笔：它说明模型**识别出**给它的那条历史与本次失败无关，并且明确拒绝了那条因果。这是负对照起作用的一个正面信号，但它只说明「无关历史不会被硬套」，不说明「相关历史有用」。

## 6. 范围与限制

### 6.1 这个场景在 M0 上已经饱和（本轮最大的缺陷）

run `38932844025` 的日志尾窗里逐字写着：

```
✖ 真机实验：故意失败
这一条是故意写失败的断言
```

M0 只要读到日志就能判断「这是故意的、不必打扰」，根本不需要任何行动历史。于是本实验测的是一个**没有增量空间**的场景，结论只能是「在这里没增量」，不能推广成「相关历史没用」。

要测出「相关历史有没有用」，需要一个 **M0 无法判断的场景**：日志本身不说明原因，而那条历史才提供原因（例如失败来自一个 Hikari 自己刚改过、但日志没提到的地方）。这个场景本轮没有构造。

### 6.2 其它限制

- **每组一次调用**：没有稳定性读数，模型换个措辞就可能改变判据结果。
- **单模型、单端点**：不能推广到别的模型。
- **预热顺序**：M0 先跑（167 s），M1/M1′ 命中端点前缀缓存（约 57–60 s）。三组耗时不可比；本轮耗时不是产品读数。如果要比较耗时，应先发一次预热请求。
- **历史材料是构造的**：本机没有任何 `repository-change-executor` 跑过的记录，两条历史都是按事实形态手写的，已在文件里标 `experimental`。
- **模型不执行动作**：本轮回答只是文本，没有工具调用，因此不涉及执行器的授权边界。

---

## 7. 对 Q2 的意义

裁决要求「用读数决定要不要把 `repository-change-executor.result` 接进模型材料」。本轮的读数是：**在这个场景里接了也没用**，因为模型不接也能判断；而「接了会不会有害」这一面，本轮没有看到伤害（没有误读成已解决）。

所以本轮**既不足以支持接入，也不足以否决接入**——它只排除了「在这个场景里接入会有明显增量」这一种可能。要给出可用结论，下一步应该是换一个 M0 饱和不了的场景重做一次（同一套冻结流程、同一套判据），而不是扩大样本量。

```bash
# 1. 冻结（不调真模型，只抓产品真实请求体）

# 2. 跑三组（每组一次，不重试）
node experiments/cognition-control/run.mjs

# 3. 按冻结判据打分
node experiments/cognition-control/score.mjs
```
