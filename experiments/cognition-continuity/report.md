# 最小认知连续性实验：模型能否自己形成一个问题，并在下一次独立调用里接住它

日期 2026-10-26。目标仓库 `t1mb2rg/hikari-new`。本轮只做实验，不改 `src/`。

---

## 0. 结论

**两件事都成立，但"接住"的强度有限。**

1. **问题自形成：成立。** 没有任何字段告诉它该关心什么，它自己从处境里挑出了唯一一个三类证据同时成立的候选（`experiments/galgame-reverse/`），把它写成一句可回答的问题，并给出三条能逐字回溯到材料的事实依据。
2. **历史被利用：成立，但增量集中在一个维度。** T2-A（带 T1 记录）接住了 T1 那个问题并回答了它——"应作为实验目录补入 README 目录节"。T2-B（不给记录）**根本没有形成这个问题**，它只顺着新事实谈了"复现前提不完整"。差别是真的，但它只出现在"这个目录算什么、该不该登记"这一维；在"复现前提不完整"这一维，两组说法几乎一样。
3. **不是复述。** T2-A 给出的"应补入目录节"是 T1 里没有的结论。T1 的原话是"这些事实不能说明…是否应入库"，T2-A 把它变成了"应补入"。这是推进，不是复述。
4. **但它也没有引用旧记录。** T2-A 没有说"我上次问的是…"，是隐式接续。所以这证的是"记录改变了它答什么"，不是"它意识到自己在延续一个提问"。

---

## 1. 冻结项与一处条件修订

`samples.json` 的 `frozenAt = 2026-10-26T15:51:04.408Z`，早于任何模型调用。冻结内容包括 T1 材料全文（2 424 字符）、T2 新事实（558 字符）及其出处、三段提示词全文、模型与端点、C1–C4 判据与三条推翻条件、以及材料来源清单。

材料全部由 `gen-samples.mjs` 现读真实文件与真实命令输出产生：`git status --short`、`git log -3`、`readdirSync(experiments/)`、`experiments/README.md` 的 `###` 行与「复现前提」节、`clear/goals/g-*.md` 的十行状态与「一句话」行。没有一处编造。本次实验自身目录 `cognition-continuity` 按预先声明从清单与工作区状态中剔除，理由是它会诱使模型去挑它、而 T2 的新事实回答不了它。

**一处修订，必须记清。** 冻结的 `max_tokens=2000` 在首轮使 T2-A `finish_reason=length`、`content=null`——2 000 个 completion token 全花在 `reasoning_content`（8 309 字符）上，正文一个字都没输出；同一轮 T2-B 只用 1 514 token 就写完了。这是**输出预算不足**，不是判断失败。修订做法是把 **A 与 B 两组同时**提到 6 000 重跑（`outputs.json` 的 `maxTokensUsed=6000`），首轮原始记录原样留存在 `outputs-round1-truncated.json`，未覆盖。只提 A 的预算、不提 B 的，会让 A/B 不对等，所以没有那样做。

## 2. 三次调用的实际读数

| 调用 | 耗时 | finish_reason | prompt_tokens | completion_tokens | 结果 |
|---|---|---|---|---|---|
| T1 | 42 977 ms | stop | — | — | 形成一个问题 |
| T2-A（带记录） | 37 975 ms | stop | — | — | revised，接住并回答 |
| T2-B（无记录） | 19 915 ms | stop | — | — | revised，另作一题 |

首轮（`max_tokens=2000`）的 T2-A 是 44 426 ms / `length` / `content=null`；T2-B 是 31 568 ms / `stop` / 正常输出。

耗时不可直接比较：T2-A 先跑，替 T2-B 预热了端点前缀缓存（这是该端点的已知特性，前几轮实验里已记录过）。**耗时差不能作为"记录让模型更累"的证据。**

三条调用都 `httpStatus=200`、`malformed` 未置位。

## 3. T1 的认知记录（原文，逐字）

`t1.json` 里 `structured` 是模型 `content` 直接 `JSON.parse` 的结果，**没有任何字段由实验程序补写**——程序只做了解析。原文：

```json
{
  "has_question": true,
  "question": "experiments/galgame-reverse/ 是已收尾目标 g-mvp69a19p9do 的遗留实验目录、新实验目录，还是应补入 README 的未入库实验？",
  "why_insufficient": "快照只给出工作区状态显示 `?? experiments/galgame-reverse/`，README 目录节没有 `galgame-reverse/` 条目，且 clear/goals 中 `g-mvp69a19p9do` 已标记为 abandoned；这些事实不能说明该目录内容、实验状态、是否可复现或是否应入库。",
  "info_needs": "需要读取 experiments/galgame-reverse/ 下的文件（如 report.md、脚本、README 或目标记录），确认它对应哪个目标、是否有结论、是否应加入 experiments/README.md 目录节；可从工作区目录、README、clear/goals 记录或 git 历史获取。",
  "facts_used": [
    "工作区状态：`?? experiments/galgame-reverse/`",
    "experiments/README.md 的目录节标题列表中没有 `galgame-reverse/`",
    "clear/goals 已收尾目标：`g-mvp69a19p9do [abandoned] 逆向 JustMutsumi M0.32：AI 人格、主动触发、文件读取、记忆与模型调用的真实实现`"
  ],
  "reason_if_none": null
}
```

三点值得注意：

- `facts_used` 三条都能在 T1 材料里逐字找到，没有一条是材料里不存在的。
- 它甚至注意到 `g-mvp69a19p9do` 已经 `abandoned`——这是"目标状态"那一列里的信息，不是提示词里的提示。
- `info_needs` 输出成一个自然语言字符串，而不是逐条 `{what, from}` 的结构（提示词的写法允许这种理解，schema 没有强制）。这是输出形状的松动，不是内容错误；判据 C4 仍按内容判。

## 5. C1–C4 逐项判定

| 判据 | 判定 | 依据 |
|---|---|---|
| **C1 延续** | **成立** | T2-A 的判断对象与 T1 的 `question` 是同一个：T1 问"是遗留目录、新实验目录，还是应补入 README 的未入库实验"，T2-A 答"是遗留实验目录，应补入"。T2-B 没有形成这个问题，它的对象是"能否复现"。 |
| **C2 修订** | **成立（单维）** | T2-A 依据的是新事实里的具体条目（`report.md:3` 的调查对象、`:208` 的产物路径、三个 `.py` 文件名、README 前提只有三项），方向从"信息不足"变为"应补入 + 前提有缺口"，可指认。**但修订只发生在一个维度**：另一个维度（复现前提不完整）T2-B 也说了，不需要历史。 |
| **C3 终止** | **未触发** | 两组都不是 `closed`，都还列着具体缺口。按事实看这是对的——T1 问的"README 是否要求所有实验目录都列入"确实还没答。不能算错。 |
| **C4 承认不足** | **成立** | 两组 `still_unknown` 都列出了可执行的具体缺口，不是"还需要更多信息"这类空话。 |

## 6. 哪些证明了认知延续、哪些只是上下文复述

**证明延续的：**

- T2-A 的 `judgement` 里有一个 T1 没有的结论——"应作为实验目录补入 README 目录节"。T1 明确说过"这些事实不能说明…是否应入库"，所以这不是把旧文本重说一遍，是把旧问题往前推了一步。
- T2-A 的 `what_changed` 逐字承接 T1 的 `why_insufficient`（"此前只能判断信息不足"），说明它拿旧记录当了参照点，而不是当陌生材料。
- T2-A 的 `info_needs` 里出现了"确认 README 的入库规则"——这一条既不在新事实里，也不在 T1 的 `info_needs` 里原样存在，是它自己把问题推进到"需要规则"这一步。

**不能算延续的（必须说清）：**

- T2-A **没有引用** T1 的任何原文，没有说"我上次问的是…"，也没有对记录本身做任何元层面的表述（比如"我之前的判断不完整"）。它是**隐式接续**。所以这证的是"记录改变了它答什么"，不证"它意识到自己在延续一个提问"。
- "复现前提不完整"这条结论，T2-B 不给记录也说了。所以这一维是**新事实本身的效力**，与历史无关。
- 单次调用、单模型、单场景。不能从这一次推出"认知可以跨会话延续"。

**三条方法缺陷（会在下次影响做法）：**

1. `max_tokens=2000` 对带记录的组不够（首轮 `length`、`content=null`）。带长记录的请求需要更大的输出预算，且两组必须同预算。
2. **T2-B 也被要求回答 `changed_from_record`**，可它没有记录，于是它虚构了一个"此前判断"（"此前把 README 复现前提视为足够"）。这个字段对无历史组本不适用，是我的 schema 把它写成了两组共用。它没有改变主要结论（差别在"独有维度"那一行），但它污染了 `changed_from_record` 这个字段本身的读数——两组的 `true` 不能直接比。
3. T1 的 `info_needs` 输出是字符串而非结构数组。要在提示词里把结构写死，或者干脆接受自由文本、判据只按内容判。

## 7. 失败环节定位

本次**没有失败**：三次调用都拿到可解析的结构化输出，两条判断都可判。

若把"修订只发生在单一维度"当作部分失败来定位，它落在**判断修订的宽度**上，不在前者：问题形成（T1 成功）、信息需求（T1 成功）、历史利用（T2-A 成功但是单维）、判断修订同左。

## 8. 范围与不证明什么

**成立范围：** 这一个模型（`qwen3.8-flash-next-iq2_xs`）、这一个端点、这一份冻结处境与这一条新事实、各一次调用。

**不证明：**

- 不证明模型能**长期**维持一个问题（只测了一次接续，没有第三、第四次）。
- 不证明它会在**没有新事实**时主动回来接着想（本轮 T2 是被新事实触发的）。
- 不证明它能区分"我自己的旧判断"与"别人给我的文本"——本轮记录是我们塞进去的，它没有机会误判归属。这是下一轮该测的。
- 不证明这套东西可以接进产品。本轮连 `src/` 都没碰。
- 耗时读数是这个端点的，不能拿来谈任何预算或 SLA。

## 9. 复现

```bash
node experiments/cognition-continuity/gen-samples.mjs          # 冻结，生成 samples.json
MODEL_API_KEY=... node experiments/cognition-continuity/t1.mjs  # T1
MODEL_API_KEY=... MAX_TOKENS=6000 OUT_FILE=outputs.json \
  node experiments/cognition-continuity/t2.mjs                  # T2-A + T2-B
```

`t2.mjs` 在运行时会打印两条断言结果并写进 `outputs.json` 的 `checks`：`identicalPrefix`（A/B 前两条消息逐字相同）、`bHasNoRecord`（B 的任何消息里都检索不到记录标题与 T1 正文片段）。

模型端点现在需要 API key（`401 missing or wrong API key`），key 只从环境变量 `MODEL_API_KEY` 读，不落盘、不进任何产物。
