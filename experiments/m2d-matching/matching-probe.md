## 为什么要这一刀

M2-c 的真实运行里，B1 会话用自然中文提问，三次 `search_memories` 加一次 findings 侧 `search_memory` 全部空集（`experiments/m2c-live/s3-recall.md:17-20`）；B2 把措辞对成正文短语「Memory 修订约定」后一次命中。原因在 M2-c 时点的 `hikari-native/memory/recall.js:122`（当时的整串子串判定；M2-d 后该行已移，现行实现见 `matchStrength`）：

```js
if (!record.text.toLowerCase().includes(input.needle)) continue
```

整串子串匹配：模型的问法与正文差一个字、或多一个空格，就一条都找不回来。这一刀要回答的是——**换一种字面口径能不能救回来，代价是什么**。

## 逐条读法

**A（现状）** 只命中 B2 那两条把正文短语抄进去的 query（`Memory 修订约定`、`修订`）。B1 四条真实问法全 0——与 M2-c 的现场一致，不是探针造出来的。

**B（多词与）** 救回 `revise memory 旧记录`（正文有 `revise`/`memory` 词元与「旧记录」）和 `串行队列 单进程`（两个词都出现在正文）。但中文没有词边界：`hikari 记忆修订` 的「记忆修订」是一个整块，正文写的是「修订约定」，两边互不包含，仍 0。**中英混排时的空格不能当词边界用。**

**F（bigram 覆盖率）** 中文问法被救回来了：`hikari 记忆修订` 覆盖率 0.75、`记忆 修订 约定` 0.67、`revise memory 旧记录` 1.0。代价是三类误命中：

- `TypeScript 编译错误` → 实测命中的片段只有 `pe`、`es`、`ri`、`pt`（record1 4/12 = 0.333；record2 多一个 `cr`，5/12 = 0.417），来源是 `supersedes`、`script`、`store.mjs` 这些代码词；
- `npm test 跑多久` → 命中 `np`、`pm`、`te`、`es`、`st`（5/7 = 0.714），来源分别是 `appendinput`/`nput`/`invalid_input`（np）、`development/m2`（pm）、`writeFile`/`update`/`delete`/`edited`（te）、`supersedes`（es）、`store`（st）；
- `how to revise a memory without losing history` → 英文问法的 bigram 与正文里的 `memory`/`revise` 撞上，5 条英文片段里中 2 条就过线。

也就是说：**拉丁字母的 bigram 撞车率太高**，纯 bigram 口径会同时放过无关 query 和纯英文问法。

**E（拉丁按词元 + 中文 bigram）** 拉丁侧改成「被正文某个词元包含」，三类误命中全部消失（`typescript` 不匹配 `script`，`npm` 不匹配任何词元，英文问法里的 `how`/`without`/`losing`/`history` 不在正文词元里），中文侧仍保留 bigram 救回能力。E0.25 在 1 条记录（B1 时点）下把 B1 四条现场原文全部救回、**0 误命中**。

**E 的阈值**：0.25 与 0.30 只差一条 query——`memory 修订 规则 是什么` 的中文四个片段（`修订`/`规则`/`是什`/`什么`）里只中 `修订`，覆盖率 0.25；0.30 挡掉它，0.25 放行。0.34 再往下掉：`hikari 记忆修订` 的中文侧 1/3 = 0.33、`记忆修订` 同样 0.33 都被挡。所以阈值取 0.25，是「四个片段里中一个」这条线。

**仍未救回的**：`两次修改同一条记忆`（与正文只共用「同一」一个片段，1/8 = 0.125，低于 0.25；正文用「修订」「链头」「旧记录」）、纯英文问法（正文全中文，字面口径没有可对的东西）、`记忆`（单字词退回整串子串，正文没有「记忆」二字）。这是字面匹配的天花板，不是阈值问题。

**D（单字覆盖率）** 两档都是 12/12 全中，但靠的是常见字：`完全不存在的词` 的 0.714 来自 `完`/`不`/`存`/`在`/`的` 五个字（片段命中只有「存在」一条，1/6 = 0.167）。**单字覆盖率不可用**——阈值 0.34 与 0.50 读数完全一样，说明它坏在性质上，不在档位。

## 结论：部分够

1. **字面口径能救回 B1 的真实问法**——把「整串子串」换成「拉丁词元按词元包含 + 中文 bigram 覆盖率 ≥ 0.25」，B1 四条现场原文从 0 命中变成 4/4 命中（在 B1 时点的 1 条记录快照上各命中 1 条），且在 7 条期望不命中的 query 上 0 误命中。
2. **救不回两类**：与正文几乎无共同片段的换义说法（`两次修改同一条记忆` 只中「同一」1/8）、纯英文问法。前者要词表或向量，后者要翻译或双语索引——都不是调阈值。
3. **证据强度有限，必须写清**：记录只有 1–2 条（同一份约定的两个版本），19 条 query 里 13 条由我构造。B1 四条与 B2 两条是现场原文；构造集能证伪（D 的误命中、F 的拉丁撞车、英文问法都是这样被抓出来的），但证明力不如真实语料。上生产前应拿真实 store 重跑。
