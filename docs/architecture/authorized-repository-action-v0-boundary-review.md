## 0. 这一片要回答的，其实是"它第一次可以弄坏东西"

今天所有能力要么是**只读查询**，要么是**自己内部的事实写入**（`hikari-current.md` §9 逐字：「没有任何一条真实副作用经过统一治理链」）。`core-architecture-v0.md` §4.4「Action：改变现实」是四个平面里**唯一零实现**的一个。

这一片之后，第一条保证会改变：

> **今天：模型的错误最多产生一句错话。**
> **这一片之后：模型的错误可以产生一次真实的改动。**

这条代价无法靠机制消除，只能靠**范围可回退、证据可见、报告不藏**来承担。本评审把这三样都写进边界。

## 1. 形状：一条链，不是一个模块

Human 的目标里有五件事。**一个模块同时拥有这五件，就是 §11 禁止的中央 Judgement + Super Orchestrator。**

| 段 | owner | 今天的状态 |
| --- | --- | --- |
| **理解需要** | Language | **已有**（模型 + tool loop + 对话连续性） |
| **这次要不要动** | —— | **本片不设 owner**（见 §2） |
| **真的去动** | 新的 Action owner | **零实现** |
| **记录做过什么** | Chronicle | **已有**（缺一个家族） |
| **报告结果** | human-delivery / Language | **已有** |

**所以缺的是两段：行动本身，以及承载 mandate 的东西。**

## 2. 本片最重要的决定：**人说的那句话是 mandate，模型的解释不是**

Human 的表述是「通过我自然对话中**能识别我需要什么**」。这句话有两种实现，而它们分属两个架构：

| | 形状 | 后果 |
| --- | --- | --- |
| **L1（建议）** | 人用**一个词**带着他那句话进来（同 G-1 的 `screen` 形状）。**那句话原文就是 mandate**。模型可以把 mandate **落成具体动作**，但它是**关于"被要求了什么"的证据**，**不是授权**。 | mandate 的主语是人；模型的错误最多让动作**做偏**，不会让动作**越权** |
| **L2（建议否决）** | 给 Language 的 tool loop 加一个**可写工具**，让模型自己调。 | **模型成了动作的作曲者**，mandate 退化成模型的转述——`Code guards truth; models interpret meaning` 当场失效 |

**本片取 L1，理由与 G-1 同源**：G-1 已经确立「窗口正文是**材料**，不是模型可以调用的 capability」。这里同理：**人的句子是 mandate，不是模型可以改写的意图**。

由此得到本片的三条不变量：

1. **mandate 原文不改写地进入记录**（模型可以附一段"我理解成了什么"，但那是**解释**，不是 mandate）。
2. **模型的解释不构成动作范围**（范围由 §4 的声明 + mandate 共同决定）。
3. **"要不要动"不由 Hikari 判断**——它由人的句子带来。这一条让本片**不构成 R4 意义上的 jurisdiction expansion**，而这是本片能否不撞 §6 的关键。

## 3. 三个必须先裁决的问题

### 3.1 可改仓库的**声明形状**

今天已有 `hikari focus declare|replace|clear|status`：**人类显式声明的对象集合**，用途是 **relevance 判断，只读**（`work-focus`）。

| 选项 | 说明 | 评价 |
| --- | --- | --- |
| **A1 复用 `work-focus`** | 给同一个声明加"可写"语义 | **不建议**。一个声明带两种权限；而 `work-focus` 的 concern 是「**我在做什么**」，不是「**哪些仓库可以被改**」。两件事混在一起，`work-focus` 的语义会变成两个 |
| **A2 另立一个显式声明**（建议） | 同型于 `work-focus`（人类显式声明、显式读 / 替换 / 清空、state 在 activation 闭包内），但**不同的 concern 与不同的权限** | 每个 concern 一个 owner，符合 §7 局部自治；权限的差异写在两个地方而不是一个 |

**建议 A2。** 但要如实说：**A2 意味着"声明"这件事会有第二个实例**，于是「要不要抽一个通用的 designation 机制」这个问题会出现。**本片不做**（见 §7）；触发条件是第三个同型声明出现。

### 3.2 授权形状：**持续 vs 每次**

G-1 立的形状是**一个词、请求局部、零状态**，代码里逐字：「授权不能比携带它的那次调用活得更久」。

而"我授权给他的仓库"听起来是**持续授权**——那是 state，与 G-1 反着来。

**这两者可以并存，仓库里已经有一句话说明怎么并：**

> **一条 standing grant 授予的是通道，不是判断。**

| 层 | 是什么 | 形状 | 主语 |
| --- | --- | --- | --- |
| **持续层（通道）** | "哪些仓库可碰" | 人类显式声明的集合（§3.1 的 A2） | **人类**，一次点名，显式可改可清 |
| **每次层（判断）** | "这一次动不动" | **一个词**，请求局部，零状态 | **人类**，每一次 |

**关键**：持续层**不是** Hikari 推出的（那会是 Hikari 自己扩权），它是**人写下的 designation**。而每次层的词，保证"声明里有这个仓库"**不等于**"这一次可以碰它"。

### 3.3 证据要求：**"它说它改了"不等于"它改了"**

这是本片最容易漏的一条，也是这个仓库最珍视的东西的落点。

**一次动作的结果不是一个布尔值**，而是一条**可核对的记录**：

```text
范围     哪些文件被碰过（来自执行者之外的可核对来源，不是它的自述）
证据     改动的 diff 摘要 / 测试的退出码 / （适用时）CI 的 run
未做到   它没能做的事（超时、被拒、部分完成）
结果     三态，见 §5.2
```

**并且**：执行者的自述**不得**被记成已核实事实。它说的是"我改了什么"，记录要写"它报告它改了什么，证据是这些"。

## 4. 行动本身：机制边界

**执行者**：一个有边界的子进程。**同型于已有先例**——`desktop-content-read` 起 PowerShell 子进程（带 timeout 与 maxBuffer），所以**不新增通信平面**。

但要如实指出一处**不同**：那个先例是**探针**（只读、短、失败等于没发生）；这一片的执行者是**工人**（可写、长、**失败不等于没发生**）。这个差别直接决定 §5.2。

**范围**：只有 §3.1 声明里的仓库；工作目录固定在该仓库内。

**启动条件（全部满足才启动）**：

1. 有一个词带来了一条 mandate（§2 L1）；
2. mandate 指向的仓库在**人类声明的可改集合**里；
3. 执行者可达。

**任何一条不满足 → 不动，且如实说明是哪一条不满足**（fail-closed，同 G-1：正文读不出来就 `failed`，模型一次都不调用）。

---

## 5. 记录：新的 durable fact 家族

### 5.1 家族形状

新家族记录**一次动作**。它必须含：

- **mandate 原文**（人的那句话，**不改写**）
- **仓库标识**（声明的那个）
- **执行者标识**（谁做的）
- **结果三态**（§5.2）
- **证据引用**（diff / 测试 / CI）
- **发生的时刻**（`occurredAt`）

**它不记**：Hikari 对结果的**解释**。那是 Awareness 的事，不是事实层的事。

### 5.2 结果必须是**三态**，不是成功/失败

这是本片一个不能省的设计，因为**写入的超时与读取的超时语义相反**：

| 态 | 含义 | 什么时候 |
| --- | --- | --- |
| `changed` | **确定改了** | 执行者正常结束且证据齐备 |
| `unchanged` | **确定没改** | 启动前就 fail-closed（§4），或执行者明确报告未做任何改动 |
| **`unknown`** | **不知道改没改** | **超时、被杀、执行者中途失联** |

**`unknown` 不得塌缩成 `unchanged`。** 一个超时的动作**可能已经改了东西**，把它报成"没改"是在说一句关于现实的假话。这与仓库既有的「**未知不得塌缩成缺席**」（感知层的一条既有语义）同源。

## 6. 它会顶到 §10 的哪一条，以及为什么本片不需要先解决它

**会顶到「完整权限系统」**（`core-architecture-v0.md` §10 明确延后）。§10 的触发条件逐字是：

> **真实实现已经出现无法被当前模型正确表达的问题。**

**但本片不需要先有权限系统**，理由是结构性的：

- 本片的**每一次动作都有一条人的句子作为 mandate**，所以"谁授权"这个问题**有答案**；
- 权限系统要回答的是"**没有人的句子时怎么办**"——**而本片不做那种动作**（§7 明确不做）。

**所以本片会把它顶到台面上（那是一件好事），但不假装解决它。**

---

## 7. 明确不做

- **不做**"它自己决定要不要动"（§2 第 3 条）；
- **不做** Goal 系统、Memory reactivation、能力发现 / 注册表 / 动态加载；
- **不做**多执行者抽象（第一个执行者就写第一个）；
- **不做**跨设备、不做远程动作；
- **不做**自动重试 / 自动修复 / 自动回滚；
- **不做**通用的 designation 机制（§3.1 已记触发条件：第三个同型声明出现时再谈）；
- **不做**任何"无人句子"的动作；
- **不把**执行者的自述记成已核实事实。

## 8. 裁决（2026-10-13，已作出）

1. **§2 取 L1。** Human 逐字：「我的原句授权然后模型去做」。
2. **§3.1 取 A2**：另立一个「可改仓库」的显式声明，**不复用** `work-focus`。
3. **§3.2 两层授权成立**：持续层是通道（Human 点名的声明），每次层是 mandate（原句）。
4. **§5.2 三态结果成立**，`unknown` 不得塌缩成 `unchanged`。
5. **执行者第一次被允许做到 (iii)：commit + push + 看 CI。** 配套要求（否则记录在说一件比实际小的事）：**证据栏必须包含 push 之后的 CI run 号，且记录必须写明"它 push 了"**——因为一旦 push，本地回退不等于世界回退。
6. **§2 不变量 3 成立**：「要不要动」不由 Hikari 判断。本片因此**不构成 R4 意义上的 jurisdiction expansion**。

### 8.1 形状的最终表述（Human 于同日确认）

**能力承认是常设的、由外部给的；授权是逐轮的、由 Human 的句子给的；而"不可回退"与"改变边界"这两类动作要单独过一道人的关。而在授权范围之内，模型自己决定怎么做——这正是它能干活的原因。**

这条表述的参照实现是**一个真实工作的 agent**（Human 当天观察的那一个），它的六步是：原句作为这一轮唯一的 mandate 到达 → 工具集事先承认、模型加不了工具 → 模型自决调用顺序与改法、无逐动作的人在环 → 安全来自「能力集有限 + 动作大多可回退 + 边界处停下来问 + 账本完整」→ 模型不能自己扩权。**本片照抄这个形状。**

**一处必须承认的风险**（同源）：模型会**同时**握着写工具与不可信内容（仓库文件、CI 日志）。因此**它在原理上可被注入**。缓解它的不是"剥夺写工具"，而是上面那四样。若把四样里的任何一样删掉，本片就不再是这个形状。

## 8bis. 记录下来的未来方向：**更多的模型自己审批并授权**

Human 于 2026-10-13 记下这一方向，逐字：「最后我们可能会做成更多的模型自己审批并授权」。

**它其实是三个安全性差别很大的动作，必须拆开记，否则会被顺手做掉：**

| | 动作 | 安全性 |
| --- | --- | --- |
| **(1)** | 模型在**已授权范围内**做更多**审批**（动哪个文件、怎么改、要不要多跑一轮测试、什么时候放弃） | **已经在发生**，而且正是它有用的原因。可以扩大 |
| **(2)** | 模型**套用**人写的授权规则（而不是人逐次点名） | **可以走的方向**：授权仍然是人写的，被自动化的只是它的**应用** |
| **(3)** | 模型**自己写**授权规则（自己造范围） | **这是那条线。** 见下 |

**(3) 的问题不是"模型会乱来"，是事后无法对账。** 用这个仓库自己的货币说：

> 动作是人授权的时候，事后可以问「凭什么动这个仓库」，而答案指向**一个可查的人的动作**（一次点名、一句话）。
> 动作是模型自授权的时候，同一个问题的答案是「它当时觉得可以」——**而这句话不是一个可以被引用的记录**。

**更精确的一层**：**模型既写规则又套规则，审计就空了**——任何动作都能与某条它自己写的规则相符。而"人写规则、模型套规则"之下，每个动作都能对着**一段固定的文本**核。**这是唯一让审计有意义的分配。**

**这不是"永远不行"**，它有一个明确的前提：**规则本身要先变得可写**。今天"哪些仓库能改"没有任何可写的规则——只有 Human 一次一次点名。**点名点够多次之后，规则会浮现出来**；到那时，把人写的规则交给模型套用，是自然的一步。**(2) 因此是本片之后的正当方向，(3) 需要的是那个前提，不是这张评审的权限。**

**结论**：本片**不做** (2) 与 (3)，但把 (2) 记为**下一片的方向**、把 (3) 记为**需要新前提的方向**——两者都不得由本片或后续实现顺手默认掉。

## 8ter. 追加裁决与参照调研（2026-10-13，同日）

**追加裁决 7：§3.1 的「可改仓库」声明是持久的**（写入 Chronicle，重启后仍在）。理由：Human 那句话的字面是「我**给他**授权的仓库」——一次给、长期有效。**代价是撤销必须显式**，因此 `clear` 是必须的，且 `status` 必须让人随时看见「现在授权了什么」。这一条把 §3.1 里"同型于 `work-focus`"的那半句**改掉了**：同型的是**形状**（人类显式声明、显式读/替换/清空），**不是持久性**——`work-focus` 今天的 designation 在 activation 闭包内，重启为空。

**Human 指定的参照：Claude Code 与 Codex 的"自主审批"。实测两者做的都是 (2)，不是 (3)。** 三条可直接借用的形状：

1. **机械兜底，而不是更信任模型。** Codex 逐字：「**Full auto-approval is safe because commands are isolated from your system.**」它的 four approval policies 里，推荐默认 `on-request` 的定义是：**需要逃出 sandbox 时才提示；留在 sandbox 边界内的操作自动批准**（[Codex approvals](https://mintlify.wiki/openai/codex/concepts/approvals)、[Codex introduction](https://mintlify.wiki/openai/codex/introduction)）。**安全来自爆炸半径小，不来自模型的判断力。**
2. **权限分层，且低信任来源不得自我升权。** Claude Code 的权限规则是**人写的三层**（allow / ask / deny），并且 settings 里明写 `defaultMode` 的 `bypassPermissions` / `dontAsk` **不能由仓库里 checked-in 的 settings 启动**——也就是**仓库不能自己给自己授权**（[Claude Code permission modes](https://code.claude.com/docs/en/permission-modes)、[permissions](https://code.claude.com/docs/en/permissions)）。**这就是 (3) 那条线，被一条优先级规则直接封掉。**
3. **模型参与的地方，参与的是"要不要打扰人"，不是"授权什么"。** Claude Code 的 auto mode 有一个 classifier 决定**要不要弹审批**（且单独计费）；Codex 有 `execpolicy` 规则——**规则由人写，机器套用**。"模型决定要不要问" 与 "模型决定什么被允许" 是两件事，两者都把前者交给模型、把后者留给人。

### 8ter.1 由此得到一条本片现在就加的不变量

> **不变量 4：低信任来源不得自我升权。**
>
> - 「可改仓库」的声明**只能由人的显式动词写**（`declare` / `replace` / `clear`），**执行者读它，不能写它**；
> - 执行者**不能**改自己的动作集（能改文件、能 commit、能 push 的那一份）；
> - mandate **不能**来自执行者的输出（§2 不变量 1 的直接推论）。

**三条都是可测的**：前两条是"执行者的代码路径里没有任何一处能写这两个声明"；第三条是"mandate 字段的来源只能是 CLI 那个词携带的人的原句"。

**Hikari 的"机械兜底"对应物**（如实记下，避免照抄一个不存在的 sandbox）：**可改仓库的声明（范围）+ git（可回退）+ 执行者的进程边界（只能在那个目录里、只能做那三个动词）**。本片**不建内核级 sandbox**——那不是本片的权限，也不是今天能诚实做出来的东西；它属于 §10「完整权限系统」那一边。

## 9. 下一步

上面六条已裁决，我按仓库流程走：**实现 → Functional Review → Architecture Review → `detect_changes` → commit / push / CI**。本片**不新增 communication plane**（Action 平面是既有平面，本片是它的第一个实现），**不改 Runtime**，**不碰 `src/runtime/**`**。

**本片不实现任何"它自己想做的事"。** 它实现的是：**一个人说一句话，一件事被真的做了，而且做完之后有证据可查、且它不会把"不知道"说成"没做"。**
