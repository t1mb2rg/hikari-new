# Hikari 终局形态

- 日期：2026-11-05
- 状态：**方向性文档，不是冻结面**。它回答"完善时是什么样"，不规定"下一步做什么"；任何一片的实现边界仍以该片自己的冻结面为准。
- 标注约定：**[判断]** 是本文的主张，可被新证据推翻；**[现状]** 是仓库里已成立的事实，附出处。

## 0. 一句话

**一个在场、连续、有出处、且知道自己不知道什么的长期合作者。**

不是更聪明的聊天机器人。聊天是它和你碰面的方式，但见面只是它生活的切片：两次见面之间，它仍然存在、仍然记得、仍然看着、仍然留着没说完的话。

## 1. 完善时的五个性质

每一条都给出可核对的判据——没有判据的性质只是形容词。

### 1.1 在场

有一个你随时能打开的地方：它记得什么、最近观察到什么、哪些事悬着、哪些它拿不准，都在那儿。

- 判据：合上所有会话之后，仍有一个不依赖会话存活的地方能显示它的状态。
- [现状] 没有。记忆在 `memory.jsonl`、拒绝样本在 `memory.rejections.jsonl`（`hikari-native/memory/rejections.js` 的 `REJECTIONS_FILE`）、findings 在各会话日志里，唯一的对外信号是一行 stderr 诊断（`hikari-native/memory/index.js:93`）。

### 1.2 连续

跨会话不断线：上次说到哪儿、哪条约定还没落实、哪个观察后来被推翻了，都还在。

- 判据：新会话里，它能不靠你复述就说出"上次的三件事分别是什么状态"。
- [现状] 记忆这一层已经连续（M2-c：`search_memories` / `get_memory` 跨 Session 可查，`19648ed`；真实验证 `aac2144`）。但"悬着的事"（目标、未决决定）没有归属，记忆只能记"发生过什么"，不能记"还欠什么"。

### 1.3 有出处

它说的每句要紧的话都能指回一行：某条记忆、某条 finding、某文件的某一行。不是"我记得你说过"，而是"你在某条里写的是这句，我据此判断"。

- 判据：随机抽它一个结论，能在文件里找到支撑它的一行。
- [现状] 部分成立。记忆记录有 `source`（指针，五种 kind，`docs/architecture/memory-core-m2-architecture-v0.1.md` §6.1），修订有 `supersedes` 链；但检索返回的是摘要，出处要靠 `get_memory` 再取一次。

### 1.4 知道边界

`occurredAt` 空的就显示空，来源回查不到的就标"回查不到"，被拒的写入留着样本。**不用平滑的语气把不确定抹掉。**

- 判据：界面上"未知"的数量不为零，并且它自己会说"这条的发生时间我不知道"。
- [现状] 数据层守住了（`occurredAt` 缺省落 `null`，不回落成 `recordedAt`；`store.mjs` 的 `validTo` 注释写着"null = 未知（不是永久）"）。但"未知"在展示层是隐形的：没有一处在告诉你"有 7 条记忆不知道发生在什么时候"。

### 1.5 克制

不自动往你脑子里塞东西，不自动替你总结世界，不主动替你决定记什么。它可以提醒，但提醒必须是它判断过"值得打断你"，而不是流水账。

- 判据：任何一次"它主动出现"，都能说出触发它的那条依据，且能关掉。
- [现状] 三条冻结前提守住了克制：不自动注入、不自动提取、不自动判断过期（M2 冻结前提 7–9）。

## 2. 完善时的一天

**[判断] 场景推演，不是承诺的功能清单。**

早上你打开那个地方：昨夜它观察到项目里三个文件变了，其中一处和它记住的一条约定冲突——页面把冲突摆出来，不给结论。旁边挂着两条昨晚记下的事，一条标着"发生时间未知"，还有一条是它想记却被校验拒掉的样本，因为它给的来源对不上。

你进会话，说"那个协议改了"。它不追问"哪个协议"——它有记忆；它引用原条、给出修订、留下旧行痕迹，然后说"改动只影响这一条，另一条依据它的记忆还成立"。会话结束，那个地方的时间线多了一行。

## 3. 三条红线

**[判断] 这三条是本文最不该被推翻的部分。**

1. **不造中央大脑。** 判断分散在各插件里，靠明确契约相连；不引入统一路由、全局状态中心、中心判断域。
2. **不自动注入。** 记忆永远由模型主动取用，任何"贴心地把记忆塞进上下文"的做法都算越界。
3. **不自动沉淀。** 记不记、记什么，是模型的判断，不是管道的副产品。

守住这三条，它才像"值得信任的长期同伴"；越过去，它就会变成"越来越懂你的系统"——后者听起来更强，但它会悄悄替你做决定。

## 4. 现在的缺口，与它们各自属于哪条线

| 缺口 | 属于 | 性质 | 现状 |
|---|---|---|---|
| 它没有钟，`occurredAt` 大量为 `null` | 运行环境 | 基础能力 | 模型不知道当前时间；[现状] `docs/architecture/cognition-action-loop-v0-boundary-review.md:68` 记着"格子无人拥有" |
| 没有一个能感知它的地方 | 展示层 | 最轻也最急 | 不存在 |
| "还欠什么"没有归属 | 领域模型 | 需要新概念（open loop / 未决事项） | 不存在 |
| 事实合起来意味着什么 | 判断层 | 最大未决问题 | 只在会话里临时发生 |
| 它能不能主动来找你 | 通信面 | 依赖判断层 | 不存在；倾向不做 |

已完成的记忆线（M2-a…M2-e）填的是"连续的底座"：存储、写入、检索、匹配粒度、拒绝留痕。它们是 1.2 的地基，但 1.1、1.3、1.4 的展示侧一直是空的——这就是"没有一个反馈的口"的来源：**架构上从没要求过它开口**。

## 5. 眼下要补的口：反馈口

**[判断] 这是现在唯一"不补就无法验证其他性质"的一块。**

"反馈"在这里有两层，缺一层都不成立：

### 5.1 模型侧：它得先说得出自己的状态

今天它连"我一共记了多少条、刚拒了哪几条"都要靠现搜现猜。需要一个只读入口，例如 `memory_status`：

- 记忆总数、最新 `seq`、最近若干条（id + 摘要 + 记录时刻 + 是否被修订）；
- 拒绝样本的条数与最近几次的错误码；
- 明确给出"发生时间未知"的条数，而不是让模型自己数。

它据此才能如实回答"你现在记得什么、刚才那条为什么没记住"。**这是只读工具，不改变任何写入契约，也不碰不注入前提。**

### 5.2 人侧：你得看得见它

一个只读的呈现：记忆（时间线 / 详情 / 修订链）、拒绝样本、以及"未知"的清单。三条硬约束：

1. **只读**：不能改、不能删、不能注入。能改的地方就不是"看它"，是"操作它"。
2. **渲染，不是真源**：所有数字从文件现算；删掉这一层，记忆本体一点不损失。
3. **不做第二套持久化**：不新增数据库、不新增后台进程。

形态上，静态页优先于命令行：命令行是"我去查一下"，页面是"它一直在那儿"。但**页面必须是本地的、随开随关的**，不起服务、不开机启动——否则就从"档案"变成"服务"，那是另一片的事。

[v0] 人侧第一版已落地：`hikari-native/viewer/render.mjs`（`--store` / `--format html|text` / `--out`），读 `memory.jsonl` 与 `memory.rejections.jsonl` 渲染三块（记忆时间线、拒绝样本、它不知道的）；6 个用例在 `hikari-native/test/memory-view.test.mjs`。模型侧（5.1）尚未实现。

### 5.3 这一层明确不做

不做控制台（改/删/注入）、不做实时窗口（那是第二步）、不做通知（那是第三步）、不做第二套真源、不因为页面好看就加字段。
