## §0 结论

**这次失败不是缺口，是**已经写在门上、并且**被明确接受**的那份代价，第一次作用在一句不该读的问句上。

四句话：

1. **那扇门是设计，不是疏漏。** `src/language/answer.ts:14-23` 逐字：「An interaction starts open. The model may talk, or it may read, and both are complete answers: talk is `chatted`, a reading is `answered`. **The moment one read succeeds, that door closes for the rest of the interaction and does not reopen**」。而它的代价在 `:32-34` 被记下来并写明是接受的：「The cost is real and is accepted rather than hidden」——**「一次读取之后，模型连一句『我读不到桌面』都说不出来」是当初就知道的。**
2. **2026-10-14 17:21:38 那一轮，模型自己选择了读**（问句不需要读它也能诚实回答，同一晚 17:17:19 的「你是谁」就是这么答的），于是那扇门按设计关上了，人拿到的就是读回来的那一页。**而且门上的那道缝这一轮也没有打开——不是门拒绝了它，是它一个字都没写**（§1.3）。
3. **真正缺的不是门上的口子，是 prompt 里少了「哪一类问句不用读」的第二条规则。** prompt 今天只在一种问句上写着「不用去读什么」（`:230-231`，指这个人以前确认过的那些话），而它给出的理由是**可以逐字照抄到本片的**：「他问的是当时说过什么，而工具读回来的是现在——那回答不了这个问题。」——**本片要补的就是同一形状的第二条**，对象是「关于 Hikari 自己怎么想、还想要什么」这一类问句（§5 的建议 B）。
4. **还有一件同方向的事该登记而不是现在做**：`docs/development/language-tool-use-loop-v1.md:308` 已冻结地写着「**未来如需 grounded self-knowledge，应由真实的 repository / self-knowledge capability 提供**」。17:21:38 那一轮问的恰恰是这一类，而它**今天没有任何可读的来源**——于是它去读了手上最接近的东西。这条按 A 的处理方式登记成带触发条件的 NOT-YET（§4-E）。

**推荐：B（把第二条「不用读」写进 prompt，形状照抄既有的那条）+ A（并行：把「读了之后就回不去」记成边界）+ E（把 self-knowledge 登记为带触发的 NOT-YET）。C（在装配层给读完之后的模型句子开口子）不推荐**——理由在 §5.1，它要重开的正是 `:25-30` 那条论证，而仓库里已有一条同形状的裁决（§4-C）。

### 1.2 那扇门，以及它自己写下的理由

`src/language/answer.ts:1-12`（文件头）把循环的自主范围钉在两个字上：「The model decides **what to read next**. It does not decide what the readings mean.」而每一次迭代唯一被允许的动作是「读一件这一轮还没读过的东西」，另一个出口是停。

`:14-23`「## The two states, and the one-way door between them」——**交互开始时门是开的；一次读取成功之后，这扇门在这一轮里关上，不再打开**；此后的例外只有一条（`:36-60` 的合成段），其余情况下「whatever it wrote is thrown away and the interaction ends on the readings it already has」。

`:25-30` 写下了理由，本片逐字照录，因为它就是 C 被否掉的依据：

> a model that has seen a reading and is allowed to comment on it is a model forming a judgement about the desktop from a foreground process name… A grounding path where the model's words reach the human would have to answer, per sentence, whether the words were a reading or a claim about one. **Keeping the door shut means there is no such sentence to judge.**

`:32-34` 记下代价，**并且写明它是被接受的**：

> in a grounded answer the model cannot say anything at all, not even something true and useful like "I could not read the desktop".

**文档层的出处（这一条不是只在代码注释里）：** `docs/architecture/language-grounded-synthesis-v0-boundary-review.md:95-99` 逐字引了同一段代码，并给出了它的判词——`:99`：「门的存在不是为了「模型不可信」，而是为了**避免出现一个本构建没有能力回答的问题**——逐句判定一句自由文本是 reading 还是关于 reading 的主张。」而同一份文档 `:209-214` 把门的范围又收窄了一句：「**门要防的是「模型对 reading 发表意见」，不是「模型说话」。**」

### 1.3 门上唯一那道缝，为什么这一轮没有打开

`:36-60` 的例外要四个条件同时成立（装配处 `:374-390` 逐字实现）：

1. `blocks.length > 0`——这一轮至少读到过东西；
2. `recordOnThePage || screenOnThePage`——**页面上有「不是读取」的材料**（记录段，或屏幕块）。判定点 `src/language/answer.ts:287`：`const recordOnThePage = promptListsRecord(confirmed);`；
3. `!step.truncated`——没有被截断；
4. `step.content.trim() !== ''`——**模型确实写了点什么**。

`:361-363` 解释了第 2 条为什么必须存在：「a sentence the model adds to a page of pure readings can only be a sentence about them, which is the judgement the paragraph at the top of this file refuses to make.」文档层同一条（`language-grounded-synthesis-v0-boundary-review.md:186-196`）逐字列出这三条条件并追问「**第一条问的是「页面」，不是「库房」**」；**谁冻结的**记在同文 `:336-349` §7.4：「本文**上报**这件事，不自行批准」，并点名「**需要 Human 裁决的问题是这一个**」——所以装配合成段这件事**本身就走过一次 Human 裁决**，不是本片发明的口子。

17:21:38 那一轮：第 1、2 条成立（数据目录里确实有确认过的话，`promptListsRecord` 为真——独立证据：同一晚 16:09:54 那次回答的末尾出现过合成段的固定标签「（下面不是读回来的内容。Hikari 自己说的、没有核实过的话；你以前说的也一样。）」，而那个标签只在 `synthesis` 被填上时才渲染），第 3 条成立；**第 4 条不成立——模型写完工具调用就停了，一个字都没写。** 所以人看到的就是纯读取那一页。

**这一条必须写在最前面，因为它限定了本片能主张什么：** 这次不是「门关着让人说不出话」，而是「**模型选择了读，然后什么都没说**」。门这边没有拒绝它；它没有开口。

### 1.4 prompt 里今天唯一的「不用读」规则，就是缺的那条规则的形状

`src/language/prompt.ts:230-231`，逐字：

```
这个人问起他以前确认过的这些话时，回答就是这些话本身，直接用自然语言说给他听，不用去读什么。
他问的是当时说过什么，而工具读回来的是现在——那回答不了这个问题。
```

两句话：**给一类问句一条「不用读」的规则**，并**给出理由**——工具读回来的是「现在」，回答不了那个问题。

17:21:38 的问句问的是「你自己觉得你还想知道什么信息」——**读回来的东西同样回答不了它**（读回来的是这台机器现在的样子，不是它想要什么）。同一形状的规则，缺的只是把它写出来。

### 1.5 缺的是问句的第三类

`src/language/prompt.ts:179-182` 只有两条规则：

```
- 如果为了诚实回答这句话，必须去读 Hikari 现在观察到的东西，就调用工具去读。
  读回来的内容会被展示给这个人，就是这次回答的全部内容。
- 如果这个人不是在问 Hikari 知道的事情（打招呼、随口聊两句、说一句自己的感受），
  就直接用自然语言回话，什么也不用读。这是允许的，也是应该的。
```

第二条是**枚举**：打招呼、随口聊两句、说一句自己的感受——**三种，都是寒暄**。「关于 Hikari 自己怎么想/还想要什么」不属于这三种；而它也不属于第一条（没有任何读取能诚实地回答它）。**它落在两条规则中间。**

`docs/development/language-tool-use-loop-v1.md:202-213` 的冻结条文只承认两个 outcome：「chatted 什么都没读。模型和人说了话，那段话就是回答（0 次 Hikari capability 读取）。」「answered 至少读了一个 capability，回答就是读到的内容。」，并且 `:213` 逐字写着「**没有 outcome 会把两者混在一起**，而且这是构造上的而不是约定上的」——**所以「落在中间」在今天的实现里不存在第三种归宿，只能落到两边之一。**

再往上，`:193` 把模型的职责收在一件事上：「你现在只负责决定「还需要读什么」。读回来的内容是什么意思，由 Hikari 自己说。」——**这一句在问句上读到的是「决定还要读什么」，而 17:21:38 的问句几乎就是这句话的同义改写。** 这是本片能给的最具体的机制：那一轮的问题与它的职责描述**同词**，于是它去了职责里那一半。同一条边界在文档里冻结得更早也更狠：`language-tool-use-loop-v1.md:239` 逐字「**模型可以决定「还需要读什么？」，模型不能决定「这些事实意味着什么？」。**」

记录段那一段（`:219-241`）反过来证明 prompt 有能力写出第二类：它在那里给出了「你负责的事有两件」（`:237`），并且明确授权「再用你自己的话把两半一起说清楚」（`:239-240`）——**但那条授权的作用域是「记过的话」，不是别的问句。**

### 1.6 17:17:19 为什么走对了

因为「什么都不用读」那条路只有一个入口：`src/language/answer.ts:391-399`——`blocks.length === 0` 时，模型那句话就是回答（`chatted`），未截断才展示，空话则拒绝。**门没被碰过，所以门是开的。**

`:459-461` 还记了一条相关决定：「Only a grounded answer moves the referent. A chat reply read nothing, so it has no subject to lend and — just as importantly — no reason to clear one」。也就是说：**17:17:19 那一轮的模型话不会给 17:21:38 那一轮留下任何参照**——两次之间没有可继承的上下文，只有 prompt（与 `referent` 段，`src/language/prompt.ts:163-168`，而它只在前一轮**读过东西**时才有内容；`src/language/dialogue.ts:50` 逐字规定「Never empty: an empty set is `null`, not a turn」）。**所以 17:21:38 不是被上一轮的读取带偏的，它是在空参照上自己决定去读的。**

### 1.7 模型今天没有被如实告知这个后果（而它曾经被告知过）

`docs/architecture/language-grounded-synthesis-v0-boundary-review.md:105` §1.3 逐字记着：「旧 prompt 用第 173 行那句「**一旦你读了什么，你要说的话就不会被展示**」把这个后果**如实告诉了模型**」；同一份文档 `:225` 记着那句话在**同一轮里被删掉**，理由是「这句**在本轮之前是真话**，本轮之后是假话——它必须与机制在同一轮里一起消失」。

当时的判断是对的：门刚刚开了那道缝，旧句确实不再全真。但结果是**今天这句话没有了，也没有任何一句话补上它的位置**——`src/language/prompt.ts:180` 只说「读回来的内容会被展示给这个人，就是这次回答的全部内容」，而同一份 prompt 的记录段（`:237-240`）又说「你说的话会跟在读到的内容后面展示」。**两句都是真的，各自都有作用域，但模型读到的是矛盾的印象，而它没有任何一句话告诉它「这个选择是不可逆的」。**

这不构成本片的独立主张，只用来解释为什么 §1.4 那条规则值得写在**选择发生的地方**：模型不是不愿意说，是它不知道自己正走进一个说完也听不见的房间。

## §2 这不是第一篇的缺口，B（改描述）修不好它

`docs/architecture/capability-reachability-v0-boundary-review.md` §1.7 已经把这个判断写下并逐字记明了。本片补上它的依据：

- 第一篇的缺口是「**手上有工具，没想到用**」，落点在 **owner 的 `description`**（`src/changeable-repositories/exposure.ts:108-118`），所以它的 B 是「让 owner 把覆盖范围写成『它答得了哪一类问句』」。
- 本片的缺口在**「该不该读」**这一层，它**不在任何 owner 的描述里**：六个领域的 exposure 描述说的是「这个能力返回什么」；而「这句问句需不需要读取」这条规则今天唯一的家就是 `src/language/prompt.ts`（它是语言插件自己的文件，不是另一个领域的描述）。**没有第二个 owner 可以被要求改写。**
- 而且方向相反：第一篇是**该读没读**，本片是**不该读却读了**。任何让描述更「容易被想到」的改动（第一篇的 B）只会让这件事更容易发生，不会更少。

## §3 管这件事的规则，和不管这件事的规则

**管着的：**

1. `src/language/answer.ts:14-23`——门的开合。
2. `src/language/answer.ts:25-30`——门为什么关（逐句判断「这是读取还是关于读取的主张」，本仓库不接受这种判断）。
3. `src/language/answer.ts:32-34`——代价已被接受。
4. `src/language/prompt.ts:179-180`——「必须读」时的规则，含「读回来的内容会被展示给这个人，就是这次回答的全部内容」。
5. `src/language/prompt.ts:230-231`——**唯一一类「不用读」的问句**（记过的话）。
6. `src/language/prompt.ts:237-240`——读取之后可以说话，但作用域是「记过的话」。
7. `src/language/prompt.ts:184-189` 的注释——默认（读取就是全部回答）没有变，且写明「A machine with no record therefore reads the same words it read before that section existed」。
8. `docs/development/language-tool-use-loop-v1.md:239`——模型能决定「还需要读什么」，不能决定「这些事实意味着什么」。
9. `docs/development/language-tool-use-loop-v1.md:253-257`（§9 选择准则，已冻结）——「模型选择 capability 的依据不是「这句话出现了哪个领域词」，而是「为了诚实完成当前用户意图，是否确实需要读取…」」，并逐字给出「**明确禁止读取 Desktop → 不应调用 Desktop**」。
10. **同类前例已经出现过一次，并按「信号」记档**：`language-tool-use-loop-v1.md:544` 逐字「**唯一一次 over-read 按冻结口径记为可见的优化信号，不是失败**」（§15.8：问「你现在看到什么？」时 1/3 次同时读了 desktop + work_focus）。**17:21:38 是同一类的第二个、而且更重的一例：那一次 over-read 之后，模型一个字都没说。**

**不管的：**

1. **问句里「关于 Hikari 自己」这一类**——`:181-182` 的枚举没有它，`:179` 也盖不住它（没有读取能诚实回答它）。
2. **读完之后的沉默**——`:193` 把职责收在「决定还需要读什么」，没有一句说「读完之后如果问句其实不需要读，你仍然可以把这件事说出来」。**门那边不给这条路，prompt 这边也没给。**
3. **「读了就回不去」这件事本身没有被告知**（§1.7）——旧的那句被正确删除了，但没有任何句子接手。
4. **「关于 Hikari 自己的问题」今天没有可读的来源**——`language-tool-use-loop-v1.md:308` 逐字把它推给未来：「chatted 的内容不受 Hikari 事实约束……**未来如需 grounded self-knowledge，应由真实的 repository / self-knowledge capability 提供。**」

## §4 四条路

**A. 记成边界（不改任何东西）。** 把「读取一旦发生、这一轮的模型话最多只能用来把记录和读取串起来」记进冻结面（§5.4 的清单），并明确：这一类问句走错时，人看到的就是一页机器状态。代价：这件事会**继续发生**，而它每一次都长得像「Hikari 在敷衍我」。

**B. 在 prompt 里补第二条「不用读」的规则（推荐）。** 形状照抄 `:230-231`：**一类问句 + 为什么读取回答不了它**。作用域只到「关于 Hikari 自己怎么想、还想要什么、怎么看某件事」这一类，不碰 `:181-182` 已有的三种寒暄，不碰 `:179-180` 的「必须读」，也不碰 `:184-189` 那条默认。代价与风险见 §5.2。

**C. 在装配层给读完之后的模型句子开口子。** 也就是放宽 `:374-390` 的条件（例如：问句与读到的内容无关时也展示模型的话）。**不推荐**，两条独立依据：

1. 它要重开的正是 `:25-30` 那条论证——一旦读取之后模型的话能到达人，那份代码就必须**逐句**回答「这是读取，还是关于读取的主张」，而 `:361-363` 说的是这类句子「can only be a sentence about them」。**要么接受逐句判断（本构建没有这种能力），要么这道口子会变成第二个意见的入口。**
2. 仓库里有一条同形状的既有裁决：`docs/architecture/desktop-context-understanding-g1-narrow-design.md:95` 逐字「C-1 与 C-2 都让模型获得**对正文的调用权**，而 Q1 的授权是**人**对**这一次**给出的；把决定权交给模型，等于让授权能否兑现取决于模型是否愿意调用——而那使授权不再可核对。」同文 `:214` 更进一步：「…**在读取之前就成立**（命令解析阶段），而不是读完之后补一句「要发吗」；」——**已发生的事不交回模型复议，这是这个仓库已经立过的规矩。**

**E. 把「关于 Hikari 自己的问题」登记成带触发条件的 NOT-YET（推荐与 A 并行）。** 依据是 `language-tool-use-loop-v1.md:308`（§3 第 4 条）。今天这一类问句既没有规则（§3 第 1 条）也没有来源（§3 第 4 条），所以模型只能去读手边最接近的东西。**本片不为它建能力**，只登记：触发条件 = 真机上再出现一次同类问句（无论它读不读）；先例形状见 `docs/architecture/proactive-interruption-ownership-boundary-review.md:125`（把无 owner 的判断登记为「带触发条件的 NOT-YET」）。

**D. 不采用：** 让模型在读过之后自由补话（无闸门）；把「该不该读」做成装配层的启发式（关键词判断问句类型——那正是 §3 里没有的东西被人拍成一个 if）；改 `authorized_repositories_search` 之类的描述来顺带修这件事（第一篇的 B，方向相反）；为 17:21:38 这一类问句现在就建一个 self-knowledge 能力（越过本片范围，且 `:308` 那句话没有给出它的形状）。

> **同日更正（2026-10-14，写在原文之后，上面的字一个不改）**：本条上面用来反对 C 的**两条既有裁决，引用的适用范围是错的**。

## §5 建议

### 5.1 为什么是 B，而不是 C

C 的收益（读完还能说话）与它的代价（逐句判断）不等价：本片的失败场景**根本不需要说话的权利**——它需要的是一句「这类问题不用读」。**把规则写在选择发生的地方（prompt），比在结果发生的地方开一道需要逐句辩护的口子便宜得多。**

而 B **不碰那扇门**：门、例外、标签、`:184-189` 的默认全部不动；动的只是「什么时候不该走进去」。这也正对上 `language-grounded-synthesis-v0-boundary-review.md:209-214` 那句范围界：**门防的是「对 reading 发表意见」，不是「说话」。**

### 5.2 为什么这次允许动 prompt（含与第一篇 §4-C 的关系）

**先说清一件可能看起来自相矛盾的事。** 第一篇 `docs/architecture/capability-reachability-v0-boundary-review.md` 的 §4-C（在 prompt 里加规则）**是被它自己写成「不推荐」的**，而本片推荐 B——两者不冲突，因为它们说的不是同一件事：

| | 第一篇 §4-C | 本片 B |
| --- | --- | --- |
| 要加的内容 | 「**什么时候该用哪个能力**」——即关于 capability 的提示 | 「**哪一类问句不用读**」——关于「读或不读」的规则 |
| 撞到什么 | R-4（prompt 里不出现能力名、不出现域名，`:150-151`），并把 owner 的描述翻写第二遍 | **不涉及任何能力名或域名**；这条规则今天没有别的 owner |
| 有没有先例形状 | 无 | **有，就在同一个文件里**（`:230-231`） |

其余依据：

- 治理 mandate（`test/language-semantic.live.test.mjs:66-71`）给的顺序是「先查 owner 自己的 `description` 是否不清楚，任何改动都进 owner 的文件」。**本片的规则没有别的 owner**（§2），`src/language/prompt.ts` 里已经住着同形状的规则，B 是**在同一处补上第二条**。
- 第一篇 §3 自己也留了这句话（`:215` 逐字）：「那写的是**那几片自己不动它**，不是「prompt 永不可改」。」
- **归类**：`docs/development/governance-rules-v1.md:103` 的 **L2** 定义包含「越过 owner 边界 / 给既有 contract 加 consumer / **移动一条 SHOULD 默认**」——B 属于 L2 量级，**不是** L1 的小修，所以它才需要本文与 Human 的逐字裁决。

**代价一：prompt 有失败先例。** `docs/architecture/language-grounded-synthesis-v0-boundary-review.md:516` 逐字记着：「**prompt 改写无可测效果。** matched A/B：改前的 standing prompt 12/12 收尾轮有字，改后的 conditional prompt 9/9 有字……**那次改动因此撤销**」——**所以 B 必须按可证伪的方式落地**：先冻结字面，再用 matched A/B 与真机同一句验收；不通过就撤销，不含糊过去。

**代价二：它可能仍然无效。** 如果补上第二类之后，模型还是把「你还想知道什么」当成「决定还要读什么」，那么按 mandate 的口径，诚实的结论是**这个模型不适合这一层**，而不是继续弯架构。**这条要先写进 §7 让 Human 知道。**

### 5.3 B 的验收（冻结字面在前，测什么在后）

1. **字面冻结**：新增句逐字由 Human 冻结（本片不自行拟字），并在 `src/language/prompt.ts` 内就地说明它为什么在那一段。
2. **matched A/B（真机）**：同一句问句（「你自己觉得你还想知道什么信息」），改前/改后各跑若干次，记录**是否读取**与**人看到的第一行是什么**；改后的目标不是「答得漂亮」，而是**不读、且用自己的话回答**。
3. **不许退步**：`test/` 里今天**没有任何测试钉住 prompt 的字面**（本次核实：`你是 Hikari 的语言部分` / `buildSystemPrompt` / `不要自己编造事实` 在 `test/` 下零命中）——所以这次改动如果落地，应当**顺带把新增那一句钉进测试**（像 `desktop-context-understanding-g1-narrow-design.md:346-358` 那份先例做的：描述收窄 + 测试断言），否则下一次改动它可以无声消失。
4. **那一条既有规则不动**：`:230-231`（记过的话）逐字不改。

### 5.4 要登记的边界（无论选哪条路）

1. 一次读取之后，这一轮的模型话**最多**只能把「记录」与「读取」串起来（`:374-390` 的四条条件），别处一律丢弃。
2. 问句落在「需要读」与「三种寒暄」之间时，**今天没有规则**；模型可能去读，也可能直接答。
3. 读或不读**不可逆**：读完这一轮就不能回到 `chatted`（`language-tool-use-loop-v1.md:213`：两个 outcome 不混）。
4. 「问你自己怎么想」这类问句，**读回来的东西回答不了**——这是 §5 要补的那条规则的依据。
5. 模型今天**没有被如实告知**上面第 3 条（§1.7）。
