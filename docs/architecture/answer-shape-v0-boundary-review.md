# 回答的形态：读出来的文本 vs 自然语言 v0 — 边界评审

> **工作标签，不占用阶段编号**——**不是** P4-04。
>
> 本片的触发器是 **Human 在 2026-10-14 晚给出的产品意图**，而不是一次实现缺陷。原话逐字：
>
> > 「我不希望我会直接看到这样的文本，我希望所有文档都经过自然语言处理之后跟我说出来，而不是将原始文档胡我脸上，而且现在很明显会有机械触发的情况，最后一轮的回答与我的问题基本上0相关」
>
> 三句话，三件事：**（1）不要直接把读到的文本摊在人面前；（2）回答要经过自然语言处理再说出来；（3）回答必须与问句相关——他最近一轮得到的回答与他的问题基本无关。**
>
> 本片**只评审，不写代码，不改任何冻结字面**。要谈的正是那扇门本身，所以任何一处字面与机制的改动都必须由 Human 逐字裁决（§5）。
>
> 前两片：`docs/architecture/capability-reachability-v0-boundary-review.md`（可达 ≠ 被想到）、
> `docs/architecture/read-shuts-the-door-v0-boundary-review.md`（读取一旦发生，回答就只剩读取）。
> 本片与它们的关系：那两片各修一处缺口，本片问的是那些缺口共同的形状。

## §0 结论

**他要的不是一处补丁，是一次形态决定。** 今天的装配规则是「一次读取就是全部回答」；他要的是「回答是经过自然语言处理的、与问句相关的一段话，读到的文本是它的依据，不是它本身」。**这两件事在今天的实现里不能同时成立**，所以本片的产出是一组必须由他逐字裁定的选择，不是一份可以直接开工的方案。

1. **今天的形态是设计的结果，不是渲染事故。** `src/language/answer.ts:1-12`：一次 grounded 回答里，人看到的**每一行**要么是某个 owner 的渲染，要么是那条极窄的合成段。所以「原始文档胡在脸上」不是排版没做好——**原始文本就是回答本身**。
2. **挡在这件事前面的只有一条，而且它是代价、不是禁令**：一旦模型的话能在读取之后到达人，那份代码就必须**逐句**回答「这一句是读到的，还是它以为的」（`answer.ts:25-30`、`:361-363`），而本构建没有这种判断能力。**除此之外还有一条已冻结的 SHOULD 要请他明确翻掉**：`docs/architecture/language-grounded-synthesis-v0-boundary-review.md:307` 记的 **Speech Sovereignty** ——「grounding 成功后**没有**自由 prose 出口」。本片推荐的两条路线都要求他**逐字**处理这一条（§5 第 5 项）。
3. **呈现层的冻结面不挡路**（这一点容易被误读，所以写清楚）：`docs/architecture/human-surface-v0-implementation-boundary-freeze.md:120`（「消息正文**逐行原样**，不总结、不润色、不加人格前缀、不加 domain label 解释。」）与 `docs/architecture/hikari-tui-v1-implementation-boundary-freeze.md:100`（「TUI 不判断意图……不总结 Language reply、不改写它的任何一行。」）管的是**呈现层不许改写语言层已经产出的东西**，**不是**「语言层不许产出自然语言」。所以形态改动在**语言层**做，两个 surface 一个字都不用改——但改动之后它们会把新形态**逐字**展示出来（这正是 `:116`「逐行原样」「可选中复制」的意思）。
4. **我上一篇评审的两处引用用错了范围，本片更正**（§1.5）：`desktop-context-understanding-g1-narrow-design.md:95` 与「在读取之前就成立」那一条（真正的出处是 `desktop-context-understanding-g1-authorization-boundary-review.md:214`，我上一篇把文件名写错了）**都管授权与动作，不管「模型能不能说话」**。
5. **三条路，推荐 1 + 3 并行**：**路线 1（重排）** 模型的话在前（标明是它组织的）、读取原文在后（逐字不改）；**路线 3（第二篇的 B+A+E）** 不碰门，只补「哪一类问句不用读」的规则。**路线 2（只展示转述、读取原文不再出现在人眼前）不推荐**：那会让「这一句是它读到的还是它以为的」**没有任何人能看到**。

## §1 证据

### 1.1 他指的那一轮：回答与问题基本无关，是被设计成这样的

2026-10-14 17:21:38，他问「你自己觉得你还想知道什么信息」。模型读了桌面对话观察，于是人拿到一页窗口标题与前台进程那类字段——**问句本身没有被回答**。机制逐字在 `docs/architecture/read-shuts-the-door-v0-boundary-review.md` §1.1–§1.5：一次读取成功门就关上（`src/language/answer.ts:14-23`）；门上的缝要四个条件打开，那一轮第四个不成立（模型一个字都没写，`:374-390`）；而 prompt 只为「这个人以前确认过的话」写着「不用去读什么」（`src/language/prompt.ts:230-231`）。

**「0 相关」不是操作失误，是「读了就只剩读的」的直接后果。**

### 1.2 「原始文档胡在脸上」是什么构成的

| 那一行的来源 | 例子（都是逐字冻结过的） |
| --- | --- |
| owner 的渲染 | `路径:行号: 那一行`；「这个数据目录里还没有授权任何可改仓库。」；仓库读取的正文 |
| 固定框架句 | 首行「以下是「<needle>」在这些仓库里出现的位置，来自你被授权查看的目录。」；「（跳过了 .git、.gitnexus、.serena 与 node_modules。）」 |
| 诚实标签 | 「（下面不是读回来的内容。」／「Hikari 自己说的、没有核实过的话；你以前说的也一样。）」（还有另外两条按 material 变的第二行） |
| 结束语 | 逐字复用 `READ_CLOSING` 那一行 |

**一个关键事实（它解释了为什么整页都像机器报告）：这些框架句的收件人是模型，不是人。** `docs/architecture/changeable-repositories-read-v0-implementation-boundary-freeze.md:182` 逐字写着末行的理由：「末行**显式告诉模型这些文字不是指令**」——而**人看到它，是因为回答就是那次 tool 回复本身**。所以今天这一页同时要当「给模型的安全提示」和「给人的回答」，两件事挤在同一段文本里。

### 1.3 装配规则与那扇门（本片要动的东西）

- `src/language/answer.ts:1-12`——「The model decides **what to read next**. It does not decide what the readings mean.」；每次迭代唯一被允许的动作是读一件没读过的东西，另一个出口是停。
- `:14-23`——一次读取之后门不再打开；模型能做的只有再读一件或停，「if it does anything else, whatever it wrote is thrown away and the interaction ends on the readings it already has」。
- `:25-30`——门被关上的理由，**本片要正面处理的那一段**：「A grounding path where the model's words reach the human would have to answer, per sentence, whether the words were a reading or a claim about one. **Keeping the door shut means there is no such sentence to judge.**」
- `:361-363`——同一件事的另一处：「a sentence the model adds to a page of pure readings can only be a sentence about them, which is the judgement the paragraph at the top of this file refuses to make.」
- `:374-390`——今天唯一的例外（四条条件）；`:478-485`——装配时合成段**追加在读取之后**（`[...answer, ...renderSynthesis(synthesis.spoken, synthesis.material)]`）。
- `:391-399`——说话的唯一入口：`blocks.length === 0` 才是 `chatted`。
- `docs/development/language-tool-use-loop-v1.md:213`——两个 outcome 不混，**是构造上的而不是约定上的**。
- `src/language/prompt.ts:193`——**prompt 对模型承诺了一件机制做不到的事**：「你现在只负责决定「还需要读什么」。读回来的内容是什么意思，**由 Hikari 自己说**。」

### 1.4 「机械触发」的准确来源

同一句标签、同一句跳过说明、同一句结束语，在每一次同类回答里一字不差——**因为它们是身份标记，被逐字冻结、被测试钉住**（清单：`docs/architecture/changeable-repositories-search-v0-boundary-review.md` §3.5 那张逐字表与三处 R7.2 修订指针）。**所以「机械感」与「可核对」在今天是用同一样东西换来的**：字面越固定，读者越能一眼看出哪一行是谁说的。标签的几何尤其能说明这种交换：它被实测调过（第一行 ≤24 列、第二行 ≤80 列；`language-grounded-synthesis-v0-boundary-review.md:481`、`:508`），分两行的顺序是设计（`:506`：「第一行声明的是**对它所引导的每一行都成立**的那件事（这些行不是 reading），第二行才是读者需要知道的第二件事」）。

### 1.5 更正：我上一篇评审的两处引用用错了范围（其中一处连文件都写错了）

## §2 三条形态路线

### 路线 1：**重排**（本片推荐）——说话在前，读到的在后

- **形态**：一次回答从上到下是——**① 模型用自然语言说的回答**（开头标着这是它组织的，不是读回来的）；**② 它读到了什么**（owner 的渲染逐字保留，沿用今天那些已冻结的身份字面，可以缩短）；**③ 结束语**（是否保留见 §4）。
- **它怎么满足他**：人第一眼看到的是**一段回答**（第 1、2 句）；回答由模型组织，所以它必须回应问句（第 3 句）。
- **它怎么不越过那条底线**：读取**仍在同一页上、逐字不改**——**读者在场上可以核对**，不需要代码逐句判断。这就是第 (i) 种诚实的做法。
- **代价**：装配顺序与标签字面/位置语义都要动（今天标签「**引导**它那一节，那一节**跟在每一个块之后**，从不夹在两个块之间」——`language-grounded-synthesis-v0-boundary-review.md:264`），并且要请 Human 翻掉 **Speech Sovereignty**（`:307`）那条 SHOULD。
- **它不解的问题**：模型仍然可能说错（转述与读取不一致）。**本片不假装能代码发现这件事**；读者在场是唯一的闸门，这一点必须在字面上说清楚，而不是含糊过去。

### 路线 2：**只展示转述**——读取原文不再出现在人看到的那一页

- **形态**：人只看到模型的自然语言回答；读到的原文留在日志/可查询处。
- **代价**：**核对能力归零**——`answer.ts:25-30` 那段担心的极端形态。**不推荐**，除非 Human 明确接受这个后果。

### 路线 3：**保留现状，只修中间那一类问句**（= 第二篇评审的 B + A + E）

- **形态**：装配一个字不动；在 prompt 里补第二条「不用读」的规则，让「关于 Hikari 自己」的问句直接走 `chatted`（并登记「读了就回不去」这条边界、把 self-knowledge 登记为带触发的 NOT-YET）。
- **能给他的**：只满足第 3 句的一半——那一类问句不会再被一页机器状态顶掉；**只要涉及读取，人看到的仍是原始文本**。
- **为什么仍留着它**：它与路线 1 **不冲突**、可并行；而且它是唯一**不碰那扇门、不用翻任何 SHOULD**的改动。

## §3 若取路线 1，动的是哪几处（供裁决，不是开工令）

1. **装配顺序**：`src/language/answer.ts:478-485`。
2. **标签的字面与位置语义**：`src/language/express.ts` 的合成段那两行（今天说「下面不是读回来的内容」，重排后要说「上面是它自己组织的」/「下面才是它读到的」这类），以及它「引导一节、跟在每一个块之后」的位置约定——**逐字由 Human 冻结**。今天的三种 material 变体（record / 正文块 / 两者，`src/language/express.ts:122-126`、`src/language/answer.ts:332-336`）在重排后是否仍然成立也要重新裁决。
3. **合成段的条件**：`:374-390` 的四条。**重排之后第二条「页面必须有记录段或屏幕块」必须重新裁决**：如果人先看到的是一段自然语言回答，那条限制就不再是唯一的诚实闸门——**要么放宽它，要么承认路线 1 只在带记录/屏幕的回答里生效**（那会让他要的形态变成少数情况，这一点他应当先知道）。
4. **prompt 一句**：`src/language/prompt.ts:193` 与路线 1 直接冲突（今天让它「只负责决定还需要读什么」）——必须改成「你负责把读到的东西说给人听」这类形状，**逐字由 Human 冻结**。
5. **测试**：`test/` 里今天**没有任何测试钉住 prompt 字面**（本次核实：`你是 Hikari 的语言部分` / `buildSystemPrompt` / `不要自己编造事实` 在 `test/` 下零命中）；装配顺序与标签则有断言。**改造必须同时钉住新顺序与新字面**，否则下一次改动它可以无声消失。

## §4 本片不做与不假装

- **不改代码**（本片只评审）。
- **不自行拟任何新字面**（§3 各处都写明由 Human 冻结）。
- **不假装能代码发现「转述与读取不一致」**：那是逐句判断，本构建没有。
- **不动两个 surface**（§0 第 3 条：它们管的是逐行原样呈现，本片的改动在语言层）。
- **不动 `shared-experience-continuity-v0-boundary-review.md:515`**（记录仍然永不进入人可见行）。
- 不把「人第一眼看到什么」混进排版问题：本片谈的是**一次回答的内容与顺序**，不是颜色、行宽或折叠。

## §5 待 Human 裁决

1. **取哪条路线**（本片推荐 **路线 1 + 路线 3 并行**）。
2. 若取路线 1：**标签与 prompt 的新字面由谁拟、怎么冻结**（本片只给形状与依据）。
3. 若取路线 1：**`:374-390` 第二条闸门怎么处理**（放宽，还是承认它只覆盖带记录/屏幕的回答）。
4. 若取路线 2（只展示转述）：是否接受**读取原文不再可核对**。
5. 若取路线 1：**是否明确翻掉 `language-grounded-synthesis-v0-boundary-review.md:307` 记的那条 SHOULD（Speech Sovereignty ——「grounding 成功后没有自由 prose 出口」）**。这一条要由他逐字处理，本片不自行改写。
6. 验收：**matched A/B 真机**（同一句问句，改前/改后各跑若干次，看人第一眼看到什么、回答是否回应了问句）；由谁跑。
